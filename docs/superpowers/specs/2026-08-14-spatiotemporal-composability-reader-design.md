# 《时空可组合性编程范式》交互导读设计

## 1. 产品目标

在 Atlas 中新增一个独立的中文论文解读页面，帮助没有形式化方法背景的普通开发者理解《A Programming Paradigm for Spatiotemporal Composability》。页面同时满足两种阅读需求：用户可以在约 10 分钟内掌握论文主张，也可以继续逐章深入理论、演算、实现与边界。

首版成功标准是读者能够：

1. 用自己的话区分时间可组合性与空间可组合性；
2. 理解 revertible effects 与 reactive coeffects 分别解决什么工程问题；
3. 通过一个插件生命周期演示，看懂加载、依赖替换与卸载如何改变系统；
4. 知道论文正式证明、Cordis 实际实现和作者仍在讨论的开放问题各是什么；
5. 随时定位回原论文的相关页码继续阅读。

页面不试图替代原论文，也不逐行重述 88 页内容。它以一条贯穿全页的插件系统案例建立直觉，再按需暴露形式化细节。

## 2. 目标读者与表达原则

目标读者是熟悉模块、服务、事件监听、热更新或依赖注入等常见概念，但不要求掌握类型论、范畴论或操作语义的开发者。

内容遵循以下原则：

- 先问题与现象，后术语与定义；
- 先用可运行的状态变化建立直觉，再展示伪代码和公式；
- 不省略关键结论，但默认折叠证明细节；
- 每个正式术语均附普通开发者解释和原论文页码；
- 明确标记“论文证明”“Cordis 实现”“工程类比”和“开放问题”，避免混淆保证范围；
- 数学符号沿用论文记法，解释文本则使用简洁中文，不创造与原文冲突的新术语。

## 3. 方案选择

采用“双层叙事式导读”，而不是机械的逐章摘要或纯交互实验室。

第一层是约 10 分钟的主线阅读，以插件的加载、运行、依赖变化和卸载为时间轴；第二层是完整导读，覆盖论文的理论构造、动态组合演算、元理论、Cordis 与 Koishi 案例。两层共享同一套术语、案例和页码索引，避免形成两个互不相干的版本。

页面包含一个轻量但真实可操作的概念演示。它用于解释论文，不承担完整框架模拟器或代码沙箱的职责。

## 4. 信息架构

### 4.1 首屏

首屏展示中英文论文标题、作者、88 页原文入口、一句话结论及两个主要行动：

- “10 分钟看懂”：滚动到速览主线；
- “进入完整导读”：跳到深入章节索引。

首屏只呈现一个中心命题：动态组件不仅要能被加入，还必须能在任意时刻被安全移除，并能随依赖的出现、消失或替换正确响应。

### 4.2 10 分钟速览

速览按五步展开：

1. 为什么重启进程是过于粗粒度的替代方案；
2. 时间可组合性：组件撤出时，只撤销自己的长期副作用；
3. 空间可组合性：组件声明依赖，并随依赖拓扑变化响应；
4. 统一 Context：环境修改与环境需求如何汇合；
5. 从局部机制到 Cordis 的动态组件系统。

每一步包含“一句话”“工程类比”“论文概念”三个层级，并给出预计阅读用时。速览结尾提供核心贡献总结与进入完整导读的自然过渡。

### 4.3 交互演示

演示位于速览中段，使用 `Database`、`Logger` 与 `AnalyticsPlugin` 三个角色。用户可依次执行：

- 加载插件；
- 提供数据库依赖；
- 将数据库由 v1 替换为 v2；
- 移除数据库；
- 卸载插件；
- 重置演示。

演示同步呈现三种视图：当前共享 Context、组件依赖拓扑、按时间排序的正向操作与逆操作日志。每个操作均附普通语言说明及其对应的 effect、coeffect、notification、activation、withdrawal 等论文概念。

为保证教学顺序，非法或当前不可用的操作保持可见但禁用，并说明前置条件。用户也可使用“下一步”按推荐路径自动推进。

### 4.4 完整导读

完整导读覆盖：

1. 动机与两个维度；
2. effects 与 coeffects 的预备知识；
3. revertible effects，包括追踪、恢复、选择性撤销和独立性直觉；
4. reactive coeffects，包括规格、通知、隔离与拦截；
5. unified context 与观察等价；
6. components、fibers 和动态组合演算；
7. preservation、时空可组合性、progress 与 confluence 等元理论结论；
8. Cordis 核心库、组件加载器、配置协调、热模块替换及 Koishi 案例；
9. 系统边界、复用、访问控制、语言选择、循环依赖、类型与版本等讨论；
10. 论文价值、适用范围与局限。

各节采用三层展开结构：默认显示直觉解释；第二层展示伪代码、小图或状态转换；第三层通过 disclosure 展开关键公式、定理结论与页码。证明只概述其作用和前提，不全文搬运。

### 4.5 速查区

页尾提供：

- 中英术语表；
- 五项核心贡献；
- 关键命题的“证明了什么 / 没证明什么”；
- 网页章节到 PDF 页码的映射；
- 原始 PDF 的打开与下载入口。

## 5. 视觉与版式

视觉采用“技术论文批注本”方向：纸张白、墨黑和低饱和灰构成主体；时间维度使用偏暖的强调色，空间/依赖维度使用偏冷的强调色，二者在 unified context 段落汇合。

排版使用清晰的内容网格和较强的标题层级，以边注、细规则线、页码标记和代码批注建立论文感。避免卡片堆叠式仪表盘、无意义徽章、装饰性渐变和过多圆角容器。公式区、代码区和正文区应在视觉上明确但属于同一编辑系统。

桌面端使用左侧章节轨道、中央正文和右侧上下文注释的宽屏结构；窄屏改为顶部简洁导航与可打开的章节抽屉，正文保持单列。阅读进度只表达当前位置，不制造完成任务的压力。

动效仅用于演示中的状态进入、退出与拓扑连线变化，并尊重 `prefers-reduced-motion`。拓扑图由可访问的 HTML/SVG 表达，不能把关键信息只编码在颜色或动画中。

## 6. 组件与数据边界

项目作为 `projects/spatiotemporal-composability/` 下独立的 React + Vite 页面接入 Atlas。

主要单元为：

- `AppShell`：组合页头、章节导航、阅读进度与正文；
- `Hero`：论文身份、中心命题和双入口；
- `QuickTour`：五步速览内容；
- `CompositionLab`：拥有演示状态并协调三个同步视图；
- `ContextView`、`DependencyGraph`、`OperationLog`：只接收派生数据并负责各自呈现；
- `DeepDive`：按数据驱动渲染完整导读章节；
- `ConceptDisclosure`：统一管理直觉、工程解释和形式化细节的展开；
- `ReferenceIndex`：术语、贡献、边界和页码映射；
- 内容数据模块：保存章节文案、术语、公式、引用页码和演示步骤，避免长篇内容硬编码在页面组件中。

原论文复制到项目 `public/`，页面通过 Vite 的 `BASE_URL` 构造链接，确保本地与 GitHub Pages 子路径均可用。

## 7. 演示状态与数据流

演示使用有限状态机，而不是任意可变对象。基础状态包括插件是否加载、可用数据库实例、插件是否激活、已注册 effects、coeffect 满足状态及操作日志。

每个用户动作先通过前置条件校验，再由纯 reducer 计算下一状态。Context 视图、依赖拓扑和日志均从同一状态派生，防止三种视图互相矛盾。撤销行为以明确的逆操作记录表达，使用户可以看见“只撤销该组件贡献”的含义。

演示是论文机制的教学模型，不宣称逐项复现 Cordis 内部实现。界面会明确标注这一边界。

## 8. 错误与降级

- JavaScript 不可用时仍显示主要导读内容、术语表和 PDF 链接；交互演示显示静态步骤说明；
- PDF 无法在浏览器打开时提供直接下载链接；
- 当前操作不满足前置条件时不改变状态，并以就近说明解释原因；
- 窄屏下拓扑图退化为有方向的依赖列表，信息不丢失；
- SVG 或动画不可用时，Context 与文字日志仍完整表达状态变化；
- 页面内容全部本地打包，不依赖运行时网络请求或外部 API。

## 9. 可访问性

- 所有演示操作可使用键盘完成，并具有清晰焦点状态；
- 状态变化通过适度的 `aria-live` 摘要通知，但不逐字朗读整个日志；
- 时间与空间两种强调色同时搭配文字标签和线型区别；
- disclosure 使用原生语义或正确的 `aria-expanded`；
- 公式附白话摘要，拓扑图附等价文本描述；
- 桌面与移动端均避免横向溢出，代码和公式区域允许局部滚动；
- 尊重减少动态效果与高对比度偏好。

## 10. 验证与验收标准

### 内容正确性

- 速览与完整导读覆盖论文五项贡献以及 Cordis 实现；
- 所有定理性表述能对应原文，页码映射与 88 页 PDF 一致；
- 工程类比、教学模型与论文正式结论有明确标签；
- 不把局部、带前提的元理论结论描述成任意软件系统的普遍保证。

### 功能正确性

- 双入口、章节导航、返回顶部、公式展开和 PDF 打开/下载均可工作；
- 推荐演示路径可从初始状态完整执行，并能重置；
- 替换或移除依赖会改变插件生命周期与拓扑；
- 卸载插件会清除自身 effects，同时保留其他组件状态；
- 禁用操作不会造成状态或三视图不一致。

### 体验与工程质量

- 普通开发者无需阅读公式即可完成 10 分钟主线；
- 桌面与手机窄屏均具有清晰层级，无裁切或横向页面溢出；
- 关键流程经过真实浏览器点击验证；
- 构建、自动化测试和可访问性基础检查通过；
- 最终实现与确认的“论文批注本”视觉方向进行桌面、移动截图对比；
- 页面可通过 Atlas 根构建脚本生成并使用正确的部署子路径。

## 11. 首版范围之外

首版不包含任意组件图编辑器、真实 Cordis 代码执行沙箱、用户账号、阅读进度持久化、评论、AI 问答、论文全文翻译、多人协作或服务端分析。这些功能不是理解论文核心机制所必需，若后续加入需单独设计。
